## `external-secrets.yaml` — External Secrets Operator

### What ESO Does

```
GCP Secret Manager → ESO (via Workload Identity) → K8s Secret → Pod env var
```

ESO replaces hardcoded credentials in manifests with a declarative `ExternalSecret` CR that fetches the real secret at runtime.

### ArgoCD Application Definition

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: external-secrets-operator
  namespace: argocd
  annotations:
    argocd.argoproj.io/sync-wave: "0"
  finalizers:
    - resources-finalizer.argocd.argoproj.io   # Deletes all ESO resources on app deletion
spec:
  project: platform

  source:
    repoURL: https://charts.external-secrets.io
    chart: external-secrets
    targetRevision: "0.12.1"    # PINNED — check releases page before updating
    helm:
      releaseName: external-secrets
      valuesObject:
        installCRDs: true   # ESO installs 16 CRDs (ExternalSecret, SecretStore, etc.)

        serviceAccount:
          create: true
          name: external-secrets
          annotations:
            # Workload Identity annotation — links K8s SA to GCP SA
            iam.gke.io/gcp-service-account: "sa-external-secrets@valiant-house-502004-k2.iam.gserviceaccount.com"

        # All ESO components run on system node pool
        tolerations:
          - key: "workload"
            operator: "Equal"
            value: "system"
            effect: "NoSchedule"
        nodeSelector:
          workload: system
        webhook:
          tolerations: [...]
          nodeSelector: {workload: system}
        certController:
          tolerations: [...]
          nodeSelector: {workload: system}

  destination:
    server: https://kubernetes.default.svc
    namespace: platform-system
```

### Workload Identity Chain for ESO

```
K8s SA: external-secrets (namespace: platform-system)
  │  annotation: iam.gke.io/gcp-service-account: sa-external-secrets@{project}.iam.gserviceaccount.com
  │
GKE metadata server sees annotation + GKE_METADATA mode on node
  │
WI IAM binding (created by argocd-bootstrap/main.tf):
  │  google_service_account_iam_member.external_secrets_wi
  │  member: serviceAccount:{project}.svc.id.goog[platform-system/external-secrets]
  │  role: roles/iam.workloadIdentityUser
  │
GCP SA: sa-external-secrets
  │  roles/secretmanager.secretAccessor (read secret values)
  │  roles/secretmanager.viewer (list/describe secrets)
  │
GCP Secret Manager
```

## `metrics-server.yaml` — Metrics Server

### What metrics-server Does

Provides CPU/memory metrics via `kubectl top` and the Metrics API. Required for:
- `HorizontalPodAutoscaler` (HPA) — `kubectl autoscale` commands
- `VerticalPodAutoscaler` (VPA) — recommendations and auto-adjustment
- `kubectl top nodes` and `kubectl top pods`

### Key Helm Values

```yaml
helm:
  releaseName: metrics-server
  valuesObject:
    # Required in some GKE versions — kubelet serving cert verification
    args:
      - --kubelet-insecure-tls

    # System pool scheduling
    tolerations:
      - key: "workload"
        value: "system"
        effect: "NoSchedule"
    nodeSelector:
      workload: system
```

`--kubelet-insecure-tls` — needed in environments where kubelet serving certs are self-signed (common in GKE). Without this, metrics-server fails to scrape node metrics.

## `priority-classes.yaml` — Pod Eviction Hierarchy

### What PriorityClasses Control

When a node runs out of CPU/memory, the Kubernetes scheduler evicts pods. PriorityClasses define the eviction order — **higher value = evicted last**.

### Four Classes Defined

| Class | Value | `globalDefault` | `preemptionPolicy` | Hosts |
|-------|-------|----------------|-------------------|-------|
| `platform-critical` | 1000 | false | `PreemptLowerPriority` | OTel Collector, Prometheus, CoreDNS, ArgoCD |
| `business-critical` | 900 | false | `PreemptLowerPriority` | Frontend, Checkout, Cart, Payment, Valkey, PostgreSQL |
| `business-standard` | 500 | **true** | `PreemptLowerPriority` | Email, Recommendation, Currency, Ad, Fraud Detection |
| `non-critical` | 100 | false | `Never` | Load Generator, chaos jobs, batch |

**`globalDefault: true`** on `business-standard` means pods without an explicit `priorityClassName` get this class by default.

**`preemptionPolicy: Never`** on `non-critical` — these pods never preempt others to schedule. They only schedule on available capacity.

### Sync Wave `0`

PriorityClasses are cluster-scoped resources. They must exist **before** any Deployment references `priorityClassName`. Wave 0 ensures they're created before business applications (wave 2).

### How Pods Reference These

```yaml
# In a Deployment spec:
spec:
  template:
    spec:
      priorityClassName: business-critical    # or platform-critical, non-critical
```

OTel Demo values files set these per-service based on criticality.
